### B-12 (P-1, review-required): narrow ALL pip/venv subprocess env + wheel-only installs

**Verified (review finding, confirmed in source):** tool `pip_requirements` is API-creatable (`schemas/tool.py:58`), and the install runs via `asyncio.to_thread` **in the server process — no Landlock, no seccomp** — on both sandbox paths (`landlock_sandbox.py:305-310`, `local_sandbox.py:175-179`). An sdist-only package runs its build/setup code as the server user: it can read `${LETTA_DIR}/server_password` (persistent after B-8) and anything else the server user can read. That's a path around L-3's closure through dependency installation. The two operator-triggered sites (`server.py:422`, `sandbox_configs.py:146,150`) pass raw `os.environ.copy()` — including `LETTA_SERVER_PASSWORD`.

**One precision (my verification):** the per-tool install path already passes the v0.16.38 allowlist env (`_gather_env_vars` at `landlock_sandbox.py:125` → `:307`), scrubbed — the raw copies are the two operator-triggered sites. This does not soften P-1: env narrowing doesn't fix unsandboxed sdist build code. Wheel-only does. Both requirements stand.

**Changes:**
1. Narrow the environment at **every** pip and venv subprocess site — the two exempted-candidates plus the per-tool install path: sandbox allowlist + what pip needs (`PATH`, `HOME` → temp dir, `PIP_*` and proxy vars if configured, SSL cert vars). pip doesn't need the server's secrets.
2. **Wheels only:** `pip install --only-binary=:all:` at every install site — no package build or setup code runs during install. A package with no wheel fails with a clear message; acceptable.
3. Delta impact: wheel-only may break a Delta tool depending on an sdist-only package → consumer notice.

**Witnesses:**
1. RED on 0.16.38: a tool whose `pip_requirements` names a local sdist with a `setup.py` that writes a marker file → install succeeds, marker written. On .39: install fails, no marker.
2. The env passed to each pip subprocess contains no `LETTA_SERVER_PASSWORD`, `LETTA_PG_URI`, `LETTA_ENCRYPTION_KEY`.

**Part C (pairs with the B-5 design round):** run installs inside a sandbox with network access but no read access to server files, and/or an owner-maintained package allowlist for tool requirements.

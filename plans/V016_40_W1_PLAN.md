## 1. W-1: single-lookup pinning

### The defect (reviewer's finding, confirmed by reading)

`message_helper.py:144` and `:170`:

```python
pinned_url = _pin_host_to_ip(url) or url
next_pinned = _pin_host_to_ip(next_url) or next_url
```

Three DNS lookups happen per fetch: `_validate_image_fetch_address` (lookup 1), `_pin_host_to_ip` (lookup 2), and — when lookup 2 returns `None` (gaierror, or any resolved address failing the public check) — httpx resolves the **unpinned** hostname again (lookup 3). An attacker controlling DNS answers lookup 1 with a public IP, fails lookup 2 (or answers it with a private IP), then answers lookup 3 with `127.0.0.1` / `169.254.169.254`. The pin exists to close exactly this window; the `or url` fallback reopens it.

### Design (reviewer's preferred option: resolve once, pin what was validated)

**One DNS lookup per URL, ever.** Validation and pinning become one operation:

- `_validate_image_fetch_address(url) -> str` — **always returns an IP or raises** (per review Q3): under the `LETTA_IMAGE_FETCH_ALLOW_PRIVATE` hatch it skips ONLY the non-public-address rejection, still resolves once and returns the IP — the hatch relaxes the address policy, it does NOT switch off pinning or create a lab-only code path. Invariant: every fetch is pinned to the IP from its single lookup, hatch or not. Redirects, content-type, and the size cap apply under the hatch too.
- `_pinned_url(url, ip) -> str` — new helper. Pure string surgery (the URL-building half of the old `_pin_host_to_ip`): brackets IPv6, preserves port/path/query. **No DNS.** The IP argument comes from validation's single lookup.
- `_pin_host_to_ip` — **deleted.** Its lookup was the window.
- Call sites (`message_helper.py:141-144` and the redirect hop at `:169-170`):

```python
# top of _fetch_image_from_url
ip = _validate_image_fetch_address(url)   # the ONLY lookup; always an IP or raise
pinned_url = _pinned_url(url, ip)

# redirect hop
next_ip = _validate_image_fetch_address(next_url)
current_url, current_pinned = next_url, _pinned_url(next_url, next_ip)
```

No `if ip else url` branches anywhere — an unpinned fetch is structurally impossible in every mode. The reviewer's original witness spec (public IP on call 1, gaierror on call 2) is moot: there is no call 2.

### Witnesses (extend `tests/test_v040_u5_vfixes.py`)

1. **`test_single_dns_lookup_per_fetch`** — counting `getaddrinfo` stub: the local-TLS fetch path (existing `img.test` rig) must call `getaddrinfo` **exactly once** for the original URL and exactly once per redirect hop. Asserts the structural property W-1 is about, not a symptom.
2. **`test_gaierror_at_validation_fails_closed`** — stub raises `gaierror` on the (only) lookup: the fetch raises `LettaImageFetchError` ("DNS resolution failed"), and no HTTP request goes out (assert on the transport mock).
3. **`test_hatch_still_pins`** (per review Q3) — with `LETTA_IMAGE_FETCH_ALLOW_PRIVATE=true`, a private-address fetch proceeds AND is pinned (the request goes to the resolved IP, not the hostname); content-type and cap still enforced.
4. **A-1 (review)** — the single-lookup counting stub counts only lookups whose host argument is NOT a numeric IP literal (`ipaddress.ip_address(host)` raises for names): the transport's instant numeric resolution of the pinned literal must not inflate the count. Assertion: exactly one by-name lookup per URL, one per redirect hop.
5. **A-2 (review)** — `_validate_image_fetch_address` pins the **first IPv4 address when there is one, otherwise the first IPv6** (an IPv6-first answer on an IPv4-capable host must not break the fetch). ## 2. Rig check 23: real public HTTPS fetch (owed item 1)

The local TLS witness proves SNI mechanics against a self-signed CA. It cannot prove a real certificate chain, a real CDN, or a real redirect. New rig check:

- **URL:** `https://commons.wikimedia.org/wiki/Special:FilePath/Example.png` — deliberately chosen because it answers with a **real 30x redirect** to `upload.wikimedia.org` (exercises redirect re-validation + SNI on a real cert chain, not just a direct fetch), and the final response carries `Content-Type: image/png` from real CDN infrastructure.
- **Mechanism:** `docker exec` into the smoke container, `python -c` calling `_fetch_image_from_url` directly — the exact production code path (guard → single lookup → pin → SNI → streamed cap → content-type), no LLM, no agent needed. Assert: bytes > 0, media_type starts with `image/`, and (from a counting wrapper) the redirect hop count ≥ 1.
- **Failure policy (per review):** guard rejection, cert failure, wrong content type, or **HTTP 403** = **FAIL** (a 403 is a policy answer, not network failure). Genuine network-unreachable (`httpx.ConnectError` / DNS failure at the rig host) = **loud SKIP with reason printed** for ad-hoc runs — but **the release-gate run recorded in the evidence doc must PASS check 23**; a SKIP there blocks the tag until it passes or Ryan waives it explicitly in the evidence.
- **User-Agent (per review):** Wikimedia's policy expects a descriptive UA with contact info and can 403 generic ones. This check sends `LettaLocal-rig/0.16.40 (+https://github.com/qfunction-ai/letta-local)` — the production fetch code gains an optional `user_agent` parameter defaulting to the `Letta/{__version__}` value, so only the rig passes the compliant UA.
- Rig count goes 22 → 23; `RIG_TARGET` unchanged.

## 3. `__version__` nit (owed item 3)

Current (`letta/__init__.py:5`): `__version__ = version("letta") or "0.16.40"` — the `or` is dead (version() raises `PackageNotFoundError`, never returns falsy), and the literal goes stale next release. Proposed:

```python
try:
    __version__ = version("letta")
except PackageNotFoundError:
    __version__ = "0+unknown"
```

- Drop the `or` (dead path — version() raises, never returns falsy).
- **No version literal anywhere** (per review): a real literal goes stale at the next release — check 20 already caught exactly that drift class. Dev checkouts show `0+unknown`, which is honest; the container always has real metadata.
- Witness: monkeypatched `version()` raising `PackageNotFoundError` -> `__version__ == "0+unknown"`.
